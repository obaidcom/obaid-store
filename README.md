# عبيد ستور | Obaid Store

متجر إلكتروني عربي بواجهة RTL، مبني على Next.js App Router وTypeScript وTailwind CSS v4 وRadix UI وLucide React وFramer Motion وخط Cairo. يستهدف المشروع تجربة تسوق مناسبة للجوال أولاً، مع فصل واجهة العملاء عن لوحة الإدارة.

> **حالة المشروع:** الواجهة الحالية ما زالت تحتوي أجزاء تجريبية. لا تعتبر المصادقة أو الدفع أو الطلبات جاهزة للإنتاج حتى يتم ربطها واختبارها فعلياً.

## المتطلبات

- Node.js 22 أو إصدار متوافق مع Next.js المستخدم.
- npm.
- مشروع Vercel للنشر.
- مشروع Supabase مخصص لمتجر عبيد بعد التأكد من أن مخططه وجداوله لا تخص تطبيقاً آخر.

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local
npm run dev
```

افتح `http://localhost:3000`. ضع الإعدادات العامة اللازمة في `.env.local` بعد التحقق من مشروع Supabase المخصص للمتجر. لا تضع مفاتيح سرية في متغيرات `NEXT_PUBLIC_*`.

## فحوصات التطوير

```bash
npm run typecheck
npm run lint
npm run build
```

## النشر على Vercel

1. اربط مستودع `obaidcom/obaid-store` بمشروع Vercel.
2. استخدم إعدادات Next.js الافتراضية وأضف متغيرات البيئة المطلوبة من لوحة Vercel.
3. اضبط `NEXT_PUBLIC_SITE_URL` على عنوان الموقع المنشور.
4. أضف عنوان الموقع نفسه إلى عناوين إعادة التوجيه المسموح بها في Supabase Auth عند تفعيل المصادقة.
5. اختبر تسجيل الدخول والجلسات ومسارات الإدارة وسياسات RLS قبل استقبال طلبات حقيقية.

لم تعد إعدادات المشروع مخصصة لتصدير GitHub Pages الثابت، لأن حماية الإدارة والتكاملات الخادمية تحتاج إلى بيئة تشغيل Next.js تدعم الخادم.

## Supabase — تنبيه قبل الربط

راجع `SUPABASE_SETUP.md` و`docs/architecture.md`. خلال مراجعة المشروع المرتبط حالياً باسم `obaid-store` ظهرت جداول `users` و`orders` و`invoices` و`settings` ببنية تبدو خاصة بتطبيق خدمات/صيانة، وليست مخطط متجر المنتجات الموجود في `supabase/schema.sql`. لم يتم تعديل قاعدة البيانات أو بياناتها. **لا تشغّل مخطط المتجر على هذا المشروع ولا تربط الواجهة به قبل تأكيد ملكية الجداول والغرض منها.**

## مبادئ الأمان

- حماية لوحة الإدارة على الخادم، وليس بإخفاء عناصر الواجهة فقط.
- تفعيل RLS على كل جدول مكشوف ومراجعة السياسات حسب نوع المستخدم والملكية.
- عدم إرسال مفاتيح `service_role` أو مفاتيح Supabase السرية إلى المتصفح أو المستودع.
- عدم اعتبار صورة إيصال الدفع دليلاً كافياً لتأكيد التحويل دون مراجعة.
- لا توجد بوابة دفع آلية مفعّلة بمجرد إظهار وسائل الدفع المحلية.

## سير العمل

تُنفّذ كل مرحلة في فرع منفصل مع commit وPull Request للمراجعة. لا يتم الدمج إلى `main` تلقائياً.
